# Roadmap

ロードマップは方向性を共有するための案です。各 Phase の開始前に、範囲、担当、完了条件、リスクを見直します。高リスク領域は専用タスクに分け、明示的な承認なしに着手しません。

## Phase 0：環境構築・開発準備

目的: 初心者 2 人が安全に並行開発できる土台を作る。

- README、Codex ルール、仕様・運用ドキュメントの整備
- GitHub のブランチ保護、PR テンプレート、レビュー手順の検討
- Next.js / TypeScript / Tailwind CSS の初期セットアップ
- Node.js バージョン、フォーマット、lint、build の標準化
- 画面・データ・API の仮設計
- 秘密情報、依存追加、高リスク領域の運用ルール確認

完了の目安: 二人が同じ手順でローカル起動でき、小さな PR を安全にレビューできる。

## Phase 1：UI プロトタイプ

目的: 実データや外部サービスを使わず、主要な操作の分かりやすさを検証する。

- 共通レイアウトとナビゲーション
- ランディング、ダッシュボード、バンド、楽曲の主要画面
- コメント、タイムスタンプコメント、TODO の UI
- モックデータを使った画面遷移
- スマートフォン向けレスポンシブ対応
- アクセシビリティの基本確認

完了の目安: 主要ユーザーフローをモックで一通り試せる。

## Phase 2：MVP 実装

目的: 小規模チームが継続して試せる最小の機能を接続する。

- DB、認証、権限方式の比較と採用判断
- バンド、メンバー、楽曲、メモ、コメント、TODO の永続化
- 最小限の招待とアクセス制御
- MIDI / 音源ファイル共有方式の決定と限定的な実装
- 楽曲バージョンの基本管理
- バリデーション、エラー処理、テスト

完了の目安: 許可されたテストユーザーが、自分のバンド内で主要機能を安全に利用できる。

## Phase 3：β版

目的: 少数の外部ユーザーから継続利用のフィードバックを得る。

- β環境と運用手順の整備
- 通知や招待体験の改善
- ファイル容量・形式・保持期間の制限
- 操作ログ、エラー監視、問い合わせ導線
- バックアップと復旧手順
- 利用規約、プライバシーポリシーの準備

完了の目安: 限定ユーザーに提供し、問題発生時に停止・調査・復旧できる。

## Phase 4：公開 v1

目的: 一般公開に必要な品質、安全性、運用体制を整える。

- 本番インフラ、ドメイン、監視、予算アラート
- セキュリティ、権限、依存関係のレビュー
- パフォーマンス、アクセシビリティ、主要端末の確認
- データ削除、退会、問い合わせ対応
- リリース・ロールバック手順
- 公開前チェックリストの完了

完了の目安: 公開責任者がチェックリストを承認し、安定運用とロールバックが可能である。

## Phase 5：収益化・運用改善

目的: ユーザー価値を保ちながら、継続運営できる形を検証する。

- 利用状況とユーザーフィードバックの分析
- 無料 / 有料プランと容量制限の設計
- Stripe などの決済候補の安全性・費用比較
- 課金、請求、解約、返金の実装と運用
- ストレージ・インフラ費用の最適化
- 継続的なセキュリティ更新と機能改善

完了の目安: 料金、コスト、サポート、法的要件を含む運用が無理なく継続できる。
