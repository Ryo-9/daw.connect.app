# Release Checklist

## 使い方

将来、β版または公開 v1 をリリースする前に使用するチェックリストです。リリースごとにコピーし、対象バージョン、責任者、確認日、結果、未解決事項を記録します。重大項目が未完了なら公開を延期します。

## リリース情報

- [ ] リリース名 / バージョン:
- [ ] 対象環境: β / 本番
- [ ] リリース予定日時:
- [ ] 実施担当者:
- [ ] 確認担当者:
- [ ] 対象 PR / commit:
- [ ] 変更内容とユーザー影響:
- [ ] ロールバック判断者:

## 1. 範囲と承認

- [ ] リリース対象の機能と対象外を確定した
- [ ] すべての PR がレビュー・承認済みである
- [ ] `main` に未確認の直接変更がない
- [ ] 仕様と実装の差を確認し、必要な文書を更新した
- [ ] 未解決の Issue を重要度別に確認した
- [ ] 公開を止める重大なバグ、セキュリティ問題、データ損失リスクがない
- [ ] リリース責任者が公開を承認した

## 2. 品質確認

- [ ] クリーンな環境で依存関係をインストールできる
- [ ] `npm run lint` が成功する
- [ ] `npm run build` が成功する
- [ ] 必須の自動テストが成功する
- [ ] 主要ユーザーフローの手動確認が成功する
- [ ] 空状態、読み込み中、エラー、権限なしの表示を確認した
- [ ] 対応ブラウザと端末で確認した
- [ ] スマートフォンで横スクロール、文字切れ、操作困難がない
- [ ] キーボード操作、ラベル、フォーカス、コントラストを確認した
- [ ] 表示速度と大きな画像 / 音源による影響を確認した

## 3. 主要ユーザーフロー

- [ ] 初回訪問から開始方法が分かる
- [ ] アカウント作成、ログイン、ログアウトが動作する
- [ ] パスワード再設定や認証失敗の導線が動作する
- [ ] バンド作成とバンド一覧が動作する
- [ ] 招待、参加、辞退、期限切れが安全に動作する
- [ ] 楽曲作成、表示、編集、アーカイブが動作する
- [ ] メモの表示・更新が動作する
- [ ] 通常コメントとタイムスタンプコメントが動作する
- [ ] TODO の作成、担当、状態変更、完了が動作する
- [ ] ファイルのアップロード、取得、削除、失敗時の再試行が動作する
- [ ] 楽曲バージョンと対象コメント / ファイルの対応が正しい
- [ ] 退会、メンバー削除、バンド解散の動作を確認した

## 4. セキュリティ

- [ ] API キー、トークン、接続文字列がコードやビルド成果物にない
- [ ] 本番の秘密情報が承認された方法で設定されている
- [ ] GitHub と本番サービスで MFA と最小権限を確認した
- [ ] セッション Cookie と HTTPS の設定を確認した
- [ ] CSRF、XSS、入力検証、レート制限を確認した
- [ ] 他のバンドや他ユーザーの URL / ID に変えてもアクセスできない
- [ ] 招待トークンの期限、失効、一回利用を確認した
- [ ] ファイルが非公開で、署名 URL の期限と権限を確認した
- [ ] ファイル形式、容量、危険ファイルへの対策を確認した
- [ ] エラー応答とログに秘密情報や個人情報が出ない
- [ ] 依存関係の既知の重大な脆弱性を確認した
- [ ] セキュリティ方針とインシデント連絡手順を二人が確認した

## 5. データと DB

- [ ] 本番 DB とテスト DB が分離されている
- [ ] スキーマ変更とマイグレーションをレビューした
- [ ] 本番相当データ量でマイグレーション時間と失敗時動作を確認した
- [ ] 変更前のバックアップを取得した
- [ ] バックアップからの復旧を確認した
- [ ] ロールバック時に DB の互換性を保てる
- [ ] 削除、退会、保持期間、バックアップ上のデータ扱いを確認した
- [ ] テストデータや開発用アカウントが本番に混入していない
- [ ] タイムゾーン、日時、文字コード、重複、最大長を確認した

## 6. ファイルとストレージ

- [ ] 本番ストレージと開発ストレージが分離されている
- [ ] 公開アクセスが無効である
- [ ] バケット / オブジェクトの権限を最小化した
- [ ] CORS、暗号化、ライフサイクル、保持期間を確認した
- [ ] 容量上限と転送量による費用上限を確認した
- [ ] 未完了アップロードと孤立ファイルの清掃方法がある
- [ ] 削除操作でメタデータとファイル本体が整合する
- [ ] 大容量、通信中断、同名、重複ファイルの動作を確認した

## 7. インフラと費用

- [ ] 本番アカウント、リージョン、環境を二人で確認した
- [ ] DNS、ドメイン、HTTPS 証明書が正しい
- [ ] 本番リソースへの操作権限が最小限である
- [ ] 予算上限と費用アラートの通知先を確認した
- [ ] ログとバックアップの保持期間を設定した
- [ ] 負荷、容量、同時アクセスの最低限の確認を行った
- [ ] 外部サービス障害時の表示と復旧手順がある
- [ ] 不要リソースを停止・削除する手順がある
- [ ] ベンダーの利用上限や無料枠終了時の影響を確認した

## 8. 監視とサポート

- [ ] エラー、可用性、認証失敗、費用の監視が動作する
- [ ] アラートが二人の確認できる場所へ届く
- [ ] アラート受信後の担当と初動手順を決めた
- [ ] ユーザーが不具合を報告できる導線がある
- [ ] 問い合わせ時に必要な情報と、収集してはいけない情報を決めた
- [ ] ステータス告知や障害連絡の方法を決めた
- [ ] リリース後の重点確認期間と担当を決めた

## 9. 法務・ユーザー説明

- [ ] 利用規約を用意し、専門家確認の要否を判断した
- [ ] プライバシーポリシーに収集情報、目的、保存、削除を記載した
- [ ] 音源・MIDI の権利と共有責任を説明した
- [ ] 外部サービスとデータ保存地域を必要に応じて説明した
- [ ] Cookie、分析、メール通知への同意要件を確認した
- [ ] 問い合わせ先と運営者情報を用意した
- [ ] 有料化する場合、料金、更新、解約、返金、税務表示を確認した

## 10. リリースとロールバック

- [ ] デプロイ手順を別の人が読んでも実行できる
- [ ] デプロイ前後の確認項目と担当者を決めた
- [ ] メンテナンス告知の要否を判断した
- [ ] 直前バックアップと復旧ポイントを確認した
- [ ] 前バージョンへ戻す手順を実際に確認した
- [ ] DB 変更を含む場合のロールバック方法を確認した
- [ ] 公開後のスモークテスト項目を準備した
- [ ] 中止条件と、誰が中止を決めるかを明確にした

## 11. 公開直後

- [ ] 本番 URL と主要画面が表示できる
- [ ] テスト用アカウントで主要フローを再確認した
- [ ] エラー率、ログ、アラート、費用を確認した
- [ ] 秘密情報やデバッグ表示が露出していない
- [ ] ファイルが意図せず公開されていない
- [ ] 問題があればロールバックまたは機能停止を実施した
- [ ] リリース結果と発生した問題を記録した

## 未解決事項と判断
